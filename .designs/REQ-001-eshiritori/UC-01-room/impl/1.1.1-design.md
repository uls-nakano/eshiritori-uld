# 設計メモ: 1.1.1 リポジトリの検証コマンドと shared kernel の土台

> タスクの範囲・変更ファイルの候補・束ね方は [tasks.md](../tasks.md) の 1.1.1 を正とし、ここには写さない。ここに書くのは、索引に無い判断・確定した影響ファイル・テスト計画・リスク。

## 1. 実装方針

### 1-1. ワークスペースと TypeScript

- npm workspaces は `["packages/*"]` だけを宣言する。`apps/*` と `tests` は、それを作る段（1.6.1・1.10.1）で足す。存在しないパスを並べると `npm install` の挙動が版に依存するため、先回りしない
- **package は TypeScript のソースをそのまま公開する（ビルドしない）。** 各 package の `package.json` は `"exports": { ".": "./src/index.ts" }`、`"type": "module"`、`"private": true`。テスト（Vitest）・型検査（tsc）・依存検査（dependency-cruiser）はソースを直接読める。サーバーの起動（1.6.1）は `tsx` などのソースを実行できるランナー、Lambda への配置は別の要求で esbuild の束ねを使う前提にする。`dist/` を作る段を挟むと、検証のたびにビルドの順番を気にすることになり、土台の段で抱える理由が無いため
- package 名は `@eshiritori/<フォルダ名>`（この段では `@eshiritori/shared-kernel`）。要確認〔名前〕
- `tsconfig.base.json`（全 package の共通設定）:
  - `strict: true`、`noUncheckedIndexedAccess: true`、`noImplicitOverride: true`、`noFallthroughCasesInSwitch: true`、`exactOptionalPropertyTypes` は入れない（OpenAPI の生成型と組み合わせると `undefined` の扱いで摩擦が大きく、得るものが少ないため）
  - `target: "ES2022"`、`lib: ["ES2022"]`（画面の `DOM` は `apps/web` の tsconfig で足す）、`module: "ESNext"`、`moduleResolution: "Bundler"`（拡張子なしの相対 import をソースのまま解決できる。`NodeNext` は `.js` 拡張子を書かせるうえ、ソース公開と噛み合わない）
  - `verbatimModuleSyntax: true`（`import type` の使い分けを型検査で強制する。rules/naming の「型のみの import は `import type`」を機械で守る）、`isolatedModules: true`、`noEmit: true`、`skipLibCheck: true`、`resolveJsonModule: true`
- `packages/shared-kernel/tsconfig.json` は base を `extends` し、`include: ["src"]` だけを持つ
- 型検査は package ごとに `tsc --noEmit` を走らせる（各 package の `"typecheck": "tsc --noEmit"`、ルートは `npm run typecheck --workspaces --if-present`）。project references（`tsc -b`）は `composite` と宣言ファイルの出力を要求し、「ビルドしない」と衝突するため採らない

### 1-2. 検証コマンド（ルート `package.json` の scripts）

既存の `check:*`（uld CLI）はそのまま残し、次を足す。段の並べ方は rules/testing の「検証コマンド」に合わせ、**段は `&&` で逐次、段の中は `run-p --continue-on-error --aggregate-output`（npm-run-all2）で並列**にする。段を表すためだけの script 名は作らず、`check` / `check:fast` の 1 行に段を書き下す。

| script | 中身 | 備考 |
| --- | --- | --- |
| `format` | `prettier --write "**/*.{ts,tsx,js,cjs,mjs,json}" "!.claude/**"` | 自動整形 |
| `format:check` | `prettier --check` 同じ対象 | |
| `lint` | `eslint . --max-warnings 0` | 判定の権威（cache なし） |
| `lint:fast` | `eslint . --max-warnings 0 --cache --cache-location node_modules/.cache/eslint/` | `check:fast` 専用 |
| `lint:fix` | `eslint . --fix` | 修正後は `lint` を通す |
| `lint:unused` | `knip` | 使われていない export・依存。要確認〔設計〕 |
| `typecheck` | `npm run typecheck --workspaces --if-present` | |
| `check:boundaries` | `depcruise packages --config .dependency-cruiser.cjs` | import 境界・循環。`apps` `tests` は作る段で引数に足す（存在しないパスを渡すと失敗するため） |
| `test` | `vitest run` | |
| `coverage` | `vitest run --coverage` | 閾値割れで失敗 |

- `check:fast` = 段 1〔`check:kit` `check:rules` `check:index` `check:trace` `format:check`〕→ 段 2〔`lint:fast` `lint:unused` `typecheck` `check:boundaries` `coverage`〕
- `check` = 段 1〔`check:branch` `check:kit` `check:rules` `check:index` `check:trace` `check:model-trace` `format:check`〕→ 段 2〔`lint` `lint:unused` `typecheck` `check:boundaries` `coverage`〕
- 単体テストは周回中もカバレッジ付き（`coverage`）で回す。いまの規模では計測の上乗せが小さく、閾値割れを周回中に見つけられるため
- `test:integration`（1.6.1）と実 DB を使うテストのレーン（1.5.1）は、それを作る段が段 2 に足す。この段には対象が無い
- ルートに `"engines": { "node": ">=22" }` を置く（実行環境の Node 22。`import.meta.dirname` を設定ファイルで使うため）

### 1-3. Prettier

- 設定はルート `package.json` の `"prettier"` キーに `{ "printWidth": 100 }` だけを置く。日本語のコメントと長い型名で 80 桁だと折り返しが増えるため
- **対象はコードと設定（`ts tsx js cjs mjs json`）に絞り、Markdown と `.claude/` を外す。** 現状のまま `prettier --check .` を流すと 29 件が整形違反になり、そのうち `rules/*/standard.md`・`.claude/skills/*`・`.claude/workflows/uld-impl.js` は kit 所有で直せない（`check:kit`・`check:rules` が版ずれとして止める）。`.claude/worktrees/` には kit の複製がローカルに残る。Markdown の整形を入れるなら docs 全体の書き換えを伴うので、別の要求で判断する。要確認〔設計〕
- `.claude/` の除外は script の否定パターンで書き、`.prettierignore` は変えない（既存の除外 `scripts/uld` `uld-kit.lock.json` `.designs` 等はそのまま効く）

### 1-4. ESLint（`eslint.config.js`、flat config）

- 全体の ignore: `node_modules/` `coverage/` `dist/` `.claude/` `.designs/` `scripts/uld/` `**/generated/**`（kit 所有・ログ資料・生成物を lint しない）
- `packages/**/*.ts`（今後 `apps/**` `tests/**` を足す）に `typescript-eslint` の `strictTypeChecked` を型情報付き（`parserOptions.projectService: true`、`tsconfigRootDir: import.meta.dirname`）で当てる。`any`・unsafe 系・non-null assertion は strictTypeChecked に含まれる
- 追加ルール:
  - `simple-import-sort/imports` と `simple-import-sort/exports`（`eslint-plugin-simple-import-sort`。import order。自動修正できる）
  - `@typescript-eslint/no-unused-vars`（未使用 import を含む。strictTypeChecked に含まれる）
  - `no-restricted-exports` の `restrictDefaultExports`（default export の禁止。ESLint 本体のルールで足りるため plugin を足さない）
  - `@typescript-eslint/naming-convention` で private member の先頭 `_` を禁止（rules/naming の「private member に `_` prefix は付けない」を機械で守る）
  - `@typescript-eslint/explicit-module-boundary-types`（公開 API に明示的な型。rules/development の「公開 API には明示的な型を付ける」）
- ルートの設定ファイル（`eslint.config.js` `vitest.config.ts`）は tsconfig に属さないため、型情報なしの `disableTypeChecked` を当て、default export を許す（ツールが default export を要求する）
- 書式のルールは入れない（Prettier に任せる）。`eslint-config-prettier` は、書式ルールを含む設定を使わないので足さない

### 1-5. 使われていない export の検出（knip）

- rules/development の Lint ルールは「unused export」の検出を求めるが、ESLint 本体と typescript-eslint には無く、`eslint-plugin-import-x` の `no-unused-modules` は flat config での動作が安定しない。knip を `lint:unused` として段 2 に置く
- 設定はルート `package.json` の `"knip"` キーに置く（ファイルを増やさない）。workspace の公開入口（`exports` の `src/index.ts`）の export は公開 API として報告対象外（knip の既定）。Vitest・ESLint・dependency-cruiser・Prettier は knip の plugin が設定ファイルから検出する

### 1-6. import 境界（`.dependency-cruiser.cjs`）

この段で入れるのは、どの package にも当てはまる一般則と shared kernel の規則だけ。package ごとの「依存してよい先」（docs/architecture の表）は、その package を作る段で足す（tasks.md の束ね方どおり）。

| ルール名 | from | to | 根拠 |
| --- | --- | --- | --- |
| `no-circular` | すべて | 循環 | rules/architecture |
| `no-production-to-tests` | `^(packages\|apps)/` | `^tests/` | テストのワークスペースを production から import しない |
| `no-package-to-app` | `^packages/` | `^apps/` | 依存は外側から内側 |
| `no-cross-package-internals` | `^packages/([^/]+)/` | `^packages/[^/]+/src/` のうち、自 package（`$1`）と `src/index.ts` 以外 | 他 module の内部 path を直接 import しない |
| `shared-kernel-depends-on-nothing` | `^packages/shared-kernel/src/`（テストを除く） | 自 package 以外のすべて（他 package・npm） | docs/architecture の「依存してよい先: なし」 |
| `domain-is-pure` | `^packages/[^/]+/src/domain/`（テストを除く） | npm の依存（workspace の `^packages/` は除く） | Domain から外部ライブラリに依存しない |
| `domain-not-to-outer-layers` | `src/domain/` | `src/(application\|adapters)/`、`packages/api-contract` | 依存方向・生成物を domain に入れない |
| `application-not-to-adapters` | `src/application/` | `src/adapters/`、`packages/api-contract` | 同上 |
| `not-to-dev-dep` | production コード（テスト・設定を除く） | devDependencies | テスト用の依存を本番に持ち込まない |
| `not-to-unresolvable` | すべて | 解決できない import | 書き間違いを検出する |

- `options`: `tsConfig.fileName: "tsconfig.base.json"`、`tsPreCompilationDeps: true`（`import type` も境界の対象にする）、`doNotFollow: node_modules`、`exclude: (^|/)(node_modules|coverage|dist|\.claude)/`、`enhancedResolveOptions` は `exports` を読み、`conditionNames: ["import", "types", "default"]`
- テストファイルは `\.test\.tsx?$` で判定する

### 1-7. Vitest（`vitest.config.ts`）

- `test.include: ["packages/*/src/**/*.test.ts"]`（`apps` は作る段で足す）。**`.claude/worktrees/` に別ブランチの複製がローカルに残るため、既定の `**/*.test.ts` にしない**（別ブランチのテストを拾って二重に走る）
- `coverage.provider: "v8"`、`coverage.include: ["packages/*/src/**/*.ts"]`、`coverage.exclude`: テスト・`**/index.ts`（再 export だけの公開入口で振る舞いを持たない）・`**/fixtures/**`・`**/generated/**`。除外理由は設定のコメントに書く
- `coverage.thresholds`: 全体 statements 85 / branches 80 / functions 85 / lines 85。glob 別に `packages/*/src/domain/**`・`packages/*/src/application/**`・`packages/shared-kernel/src/**` を 4 指標とも 100。shared kernel を 100 にするのは、domain がその上に立つ（`DomainError`・`Result` の誤りは全 module の domain の誤りになる）ため。要確認〔設計〕

### 1-8. shared kernel

#### `DomainError`（`src/DomainError.ts`）

- `abstract class DomainError<TErrorCode extends string = string> extends Error`
- `protected constructor(packageCode: string, errorCode: TErrorCode, detail: string)`。各 module の継承クラスが自分の `packageCode` を固定して `super` に渡す（例: 1.2.1 の `RoomError` は `constructor(errorCode: RoomErrorCode, detail: string) { super("room", errorCode, detail); }`）。抽象 property（`abstract readonly packageCode`）にしないのは、基底の constructor の時点で継承クラスのフィールドがまだ初期化されず、`code` を constructor で確定できないため
- 公開 property（すべて `readonly`）: `packageCode`、`errorCode`（`TErrorCode` に型付け）、`detail`、`code`（`` `${packageCode}.${errorCode}` ``）。要確認〔名前〕
- `name` は `new.target.name`（ログとスタックで継承クラス名が出る）。`message` は `` `${code}: ${detail}` ``（捕捉されずに落ちたときに識別子が読めるように）
- ログは出さない、`causeData` のような追加 property は持たない（rules/development）。`cause` の受け渡しは、use case が予期しない例外を変換する段（1.6.1 以降）で必要になったら足す

#### `Result`（`src/Result.ts`）

- 型: `Success<T>`（`readonly kind: "success"`、`readonly value: T`）、`Failure<E>`（`readonly kind: "failure"`、`readonly error: E`）、`type Result<T, E = DomainError> = Success<T> | Failure<E>`。すべて `interface` / `type` で、クラスにしない（値を運ぶだけで振る舞いを持たないため）
- 関数: `success(value)`（引数なしの `success()` は `Success<void>`。保存の成否のように値の無い成功に使う）、`failure(error)`、型ガード `isSuccess(result): result is Success<T>`、`isFailure(result): result is Failure<E>`
- `kind` は判別のための内部の印で、分岐は `isSuccess` / `isFailure` で書く（rules/development の「Result の内部 property に直接依存する分岐は避ける」）。`map` / `flatMap` などの合成は、使う段が出るまで足さない
- `E` に制約（`extends DomainError`）を付けない。リポジトリの保存の衝突（1.5.1）のように、DomainError ではない失敗の印を返す場面がありうるため。既定値だけを `DomainError` にする

#### `src/index.ts`

- `DomainError`、`success` `failure` `isSuccess` `isFailure` を named export、`Result` `Success` `Failure` を `export type` で公開する

### 1-9. 索引（`CLAUDE.md` / `AGENTS.md`）

- 「構成」の「package・app はまだありません。」を外し、`packages/shared-kernel/` の 1 行（`DomainError` 基底・`Result` など module をまたぐ最小限の共通物）を足す
- 「このプロジェクト」の「ユースケース・ドメインモデル・実装はまだありません」は設計 PR のマージで既に古いので、同じ変更で現状（ユースケース記述・ドメインモデルがあり、実装を始めた段階）に直す

### 単体テスト（観測点）

`packages/shared-kernel/src/DomainError.test.ts`（テスト専用の継承クラス `SampleError` をテストファイル内に定義して使う）

`packages/shared-kernel/src/Result.test.ts`

### 検証コマンド自体の確認（コミットしない手作業）

検証の道具は単体テストで守れないため、実装時に一度だけ「止めるべきものを止める」ことを確かめ、結果を実装の記録に残す。確かめたら作った違反は消す。

- `check:boundaries`: shared kernel から存在しない別 package の内部 path を import する・npm パッケージを import する・2 ファイルで循環させる、の各違反で失敗する
- `lint`: `any`・default export・`_` 付きの private member・並びの崩れた import で失敗する
- `lint:unused`: 公開入口から辿れない export で失敗する
- `format:check`: 整形の崩れた `.ts` で失敗し、Markdown と `.claude/` は対象にならない
- `coverage`: shared kernel の分岐を 1 つテストから外すと閾値割れで失敗する
- `check` と `check:fast`: 段 1 の 1 つを落としたとき、段 1 の残りは最後まで走り、段 2 は走らない

## 5. リスク・注意点

- **ツールの版の組み合わせ。** `typescript-eslint` は対応する TypeScript の版の範囲を持つ。最新の TypeScript が範囲外なら、`typescript-eslint` が対応する最新の版に揃える
- **dependency-cruiser の workspace の扱い。** npm workspaces の symlink 越しの import（`@eshiritori/shared-kernel`）が、実パス（`packages/shared-kernel/src/index.ts`）に解決されるか、依存の種類が `npm` と `local` のどちらで報告されるかは版で違いうる。`domain-is-pure` と `no-cross-package-internals` が意図どおりに効くかを、room を作る 1.2.1 を待たずにこの段の手作業の確認（4. の `check:boundaries`）で見る。この段では workspace 越しの import を持つ package が無いため、確認は一時的な package を作って行う
- **knip の誤検出。** ルートの devDependencies を workspace から使う形（shared kernel のテストがルートの `vitest` を import する）を、knip が「package.json に無い依存」と報告する場合は、設定（`ignoreDependencies` ではなく workspace ごとの指定）で解決する。報告を消すためだけの除外はしない
- **Vitest の glob 別閾値に一致するファイルが無い場合。** この段では `src/domain/**`・`src/application/**` に一致するファイルが無い。一致なしで失敗する版なら、その glob はファイルができる段（1.2.1・1.6.1）で足す
- **CI が無い。** rules/testing は `check` を「CI と同じ検証」とするが、リポジトリに CI のワークフローはまだ無い。この段の範囲外で、ローカルの `check` だけが門番になる
- **`.claude/worktrees/` の取りこぼし。** ここに残るローカルの複製を Prettier・ESLint・Vitest・dependency-cruiser のどれか 1 つでも拾うと、別ブランチの内容で検証が赤くなる。4 つの道具すべてで `.claude/` を除外する

## 実装の記録

### 設計からの逸脱

- **TypeScript は 7.x ではなく `~6.0.3` に固定した。** 最新の 7.0.2 は `typescript-eslint` 8.71.1 の対応範囲（`<6.1.0`）の外のため、設計 5 章のリスクに従い対応する最新へ揃えた
- **`knip` の設定は `ignore: [".claude/**", "scripts/uld/**"]` と workspace `packages/*` の `project` にした。** kit 所有のファイルを「未使用ファイル」と報告するため。entry は knip が `exports` から自動検出するので書かない（冗長の指摘が出たため）
- **`DomainError` は `code` を constructor で代入する形にした。** `super` 前に `code` を組み立てて message に使う

### 検証コマンドの手作業確認（結果）

- `check:boundaries`: 一時ファイルで、shared kernel と domain から `vitest`（npm）を import すると `shared-kernel-depends-on-nothing`・`domain-is-pure`・`not-to-dev-dep` が発火し失敗した（一時 package `tmpdom` の `src/domain/` で確認。確認後に削除）。当初は `options.exclude` が `node_modules/…/dist/` の解決先をグラフから落としており npm 依存が cruise されなかったため、exclude をリポジトリ直下と package 直下の生成物に限り、`combinedDependencies: true` を足して直した（レビュー指摘）。`no-cross-package-internals` の workspace 越し import と循環は、room を作る 1.2.1 で効くか確かめる
- `lint`: `any`・default export・`_` 付き private member・import の並びで失敗した
- `lint:unused`: 使われない export を含むファイルを報告した（検出は knip のファイル単位の報告）
- `format:check`: 整形崩れの `.ts` で失敗し、Markdown と `.claude/` は対象外
- `coverage`: 未テストの関数を足すと閾値割れで失敗した
- `check:fast`: 段 1 の 1 つを落としても残りは最後まで走り、段 2 は走らなかった
