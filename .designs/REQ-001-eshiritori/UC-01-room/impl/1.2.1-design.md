# 設計メモ: 1.2.1 room package の雛形・エラーコードと、名乗り・周回数・進行状態の値

> タスクの範囲・変更ファイルの候補・束ね方は [tasks.md](../tasks.md) の 1.2.1 を正とし、ここには写さない。値の役割と設計判断は [docs/domain/room/room-部屋集約.md](../../../../docs/domain/room/room-部屋集約.md) を正とする。ここに書くのは、索引にもモデル docs にも無い判断・確定した影響ファイル・テスト計画・リスク。

## 1. 実装方針

### 1-1. package の雛形（`packages/room`）

- `package.json` は shared kernel と同じ形（`name: "@eshiritori/room"`、`private`、`type: module`、`exports: { ".": "./src/index.ts" }`、`scripts.typecheck: "tsc --noEmit"`）に、`"dependencies": { "@eshiritori/shared-kernel": "*" }` を足す。**devDependencies ではなく dependencies に置く**（domain と errors の本番コードが import するため。`not-to-dev-dep` に当たらないようにする）。`npm install` で workspace のリンクを張り、`package-lock.json` を更新する
- `tsconfig.json` は shared kernel と同じ（base を `extends`、`include: ["src"]`）
- ルートの `package.json`・`vitest.config.ts`・`eslint.config.js`・knip の設定は変えない。いずれも `packages/*` の glob で room を拾う（1.1.1 の設定のまま）。カバレッジの `packages/*/src/domain/**` 100% の閾値は、この段で初めて一致するファイルを持つ

### 1-2. エラー（`src/errors/`）

#### `RoomErrorCode.ts`

- 文字列リテラルの union 型 `RoomErrorCode` だけを置く（実行時の値を持たない）。各メンバーに、どの要件の失敗かを日本語コメントで付ける
- **このスライスで使う 9 件をこの段でまとめて定義する。** tasks.md の後続の段（1.3.1・1.4.1・1.6.1〜1.7.2）の変更ファイルに `RoomErrorCode.ts` が無いため、段ごとに足すと各段が予定外の変更を抱える。union の未使用メンバーは型検査・knip・カバレッジのどれにも影響しない

| errorCode | 失敗 | 使う段 |
| --- | --- | --- |
| `nickname_empty` | ニックネームが空（空白だけを含む） | 1.2.1（UC-01 要件 4、UC-02 要件 9） |
| `nickname_too_long` | ニックネームが前後の空白を除いて 10 文字を超える | 1.2.1（同上） |
| `round_count_out_of_range` | 周回数が 1〜5 の整数でない | 1.2.1（UC-01 要件 5） |
| `room_not_found` | 部屋が無い・期限切れ・部屋コードの書式誤り | 1.3.1・1.7.1（UC-02 要件 4・5） |
| `room_full` | メンバーが既に 8 人 | 1.4.1（UC-02 要件 6） |
| `game_already_started` | 一度でもゲームが始まった部屋に入ろうとした | 1.4.1（UC-02 要件 7） |
| `nickname_taken` | 同じ部屋に同じニックネームのメンバーがいる | 1.4.1（UC-02 要件 8） |
| `not_host` | ホスト以外（メンバーでない人を含む）からの開始の要求 | 1.4.1（UC-03 要件 5） |
| `not_enough_members` | メンバーがホスト 1 人だけで開始しようとした | 1.4.1（UC-03 要件 4） |

- **空と長すぎるを別のコードにする。** 画面が表示する文言が違い（S-01-15「ニックネームを入れてください」、S-01-16「ニックネームは 10 文字までです」）、画面は `code` から文言を引くため（rules/development の「エラーハンドリングルール」）。周回数は 0・6・小数のどれでも文言が同じ（S-01-17）なので 1 つにする
- 二度目の開始（UC-03 要件 6）はエラーにしないので、コードを持たない（モデル docs の「二度目の開始は失敗にしない」）
- 後続の段で足りないコード（例: 待機室に戻るときの、どのメンバーでもないトークン）が見つかったら、その段で足し、要確認〔予定外〕に載せる

#### `RoomError.ts`

- `export class RoomError extends DomainError<RoomErrorCode>`。public の `constructor(errorCode: RoomErrorCode, detail: string)` が `super("room", errorCode, detail)` を呼ぶ（packageCode は `room`。`code` は `room.nickname_empty` の形）。1.1.1 の `DomainError` の設計どおりで、追加の property は持たない

### 1-3. 値オブジェクト（`src/domain/room/`）

共通の形:

- `private constructor` と static factory。実値は ES の private field `#value` に持ち、図の `-value`（private の属性）と名前をそろえる。TS の `private readonly value` にしないのは、公開の getter `value` と名前が衝突するため
- **入力を検証する factory（`Nickname.create`・`RoundCount.create`）は `Result<T, RoomError>` を返し、throw しない。** 不正な入力は利用者の操作で普通に起きる失敗で、use case（1.6.1・1.7.1）が `isFailure` で分岐して API のエラー応答に変える。例外にすると、use case が try/catch で業務の失敗と予期しない例外を区別することになる（rules/development の「成功/失敗を戻り値で扱う箇所では Result 型を使い」）
- 図の戻り値（`create(value) Nickname$`）は変えない。失敗を Result で返すかはクラスごとのモデルではなく rules/development の約束で、図に載せると全 factory の表記が Result で埋まるため（要確認〔設計〕）
- domain は失敗のログを出さない。Logger は同じフェーズの 1.2.2 で作られ、この段の入力にできない。原因の入力値のログは、失敗を API の応答に変える use case（1.6.1 以降）が出す
- `equals(other)` は `#value` の一致で判定する
- 業務の上限・下限（10 文字、1〜5）はファイル内の非公開の定数（`MAX_NICKNAME_LENGTH`、`MIN_ROUND_COUNT`、`MAX_ROUND_COUNT`）にし、export しない。画面の選択肢（1〜5）は API 契約（1.6.1）で表し、web が room を import しないため

#### `Nickname`

- `static create(value: string): Result<Nickname, RoomError>`
  1. `value.trim()` で前後の空白を除く。`String.prototype.trim` は全角空白（U+3000）・タブ・改行も除くので、空白だけの全角入力も空になる
  2. 空なら `nickname_empty`
  3. 見た目の文字数（書記素クラスタ）が 10 を超えたら `nickname_too_long`。数え方は `Intl.Segmenter`（`granularity: "grapheme"`）。モジュール直下に 1 つ作って使い回す。`[...value].length`（コードポイント）は家族の絵文字（ZWJ 連結）を 5 文字、国旗を 2 文字と数え、モデル docs の「絵文字 1 つを 1 文字」に反するため採らない。`Intl` は実行環境の組み込みで、外部ライブラリへの依存ではない（型は `lib: ES2022` の `es2022.intl` にある）
  4. 除いた後の値で `success(new Nickname(trimmed))`
- **Unicode の正規化（NFC など）はしない。** モデル docs が「比較は値の完全一致にする」としているため。結合文字で書いた「か + ゛」と合成済みの「が」は別のニックネームになる（要確認〔仕様〕）
- 文字数を数える関数はクラスの外に非公開の関数として置き、別ファイルにしない。`src/domain/` のファイルは 1 つずつモデル図のクラスと突き合わせられる（`check:model-trace` の「図に無いクラス」）ため
- `get value(): string`（API の DTO・保存の mapper が使う。図には載せない。モデル図の既存の VO と同じく、実値の getter は描かない）
- `equals(other: Nickname): boolean`

#### `RoundCount`

- `static create(value: number): Result<RoundCount, RoomError>`。`Number.isInteger(value)` かつ 1 以上 5 以下でなければ `round_count_out_of_range`。`Number.isInteger` は `NaN`・`Infinity`・小数を偽にする
- 既定値を持たない（モデル docs のとおり。引数の省略を型で許さない）
- `get value(): number`（待機室に周回数を出す DTO が使う）
- `equals(other: RoundCount): boolean`

#### `RoomStatus`

- 実値は `"waiting" | "started"` の非公開の型。`static waiting()`・`static started()`・`hasStarted()`（`#value === "started"`）・`equals(other)`
- **getter を持たない。** モデル docs が「外から実値を比べず、`hasStarted` で尋ねる」としているため。保存の mapper（1.5.1）は `hasStarted()` と `waiting()` / `started()` で行き来できる。後続の移行単位で状態が増えて足りなくなったら、その段で復元用の factory と getter を足す

### 1-4. 公開入口（`src/index.ts`）

- `RoomError` を named export、`RoomErrorCode` を `export type` で公開する
- **値オブジェクトは公開しない。** room の外の利用者（`apps/api`・`tests/`）が使うのは use case・DTO・エラーで、domain の値を外に出すと route が domain の判断を再実装する入口になるため（rules/architecture の「route は domain rule を再実装しない」）。値オブジェクトはこの段では colocate テストからだけ使われる。後続の段で公開が要るかは、その段が use case と DTO を作るときに決める（要確認〔設計〕）

足すルールは 2 つ。既存のルールは変えない。

| ルール名 | from | to | 根拠 |
| --- | --- | --- | --- |
| `room-depends-only-on-shared-kernel` | `^packages/room/` | `^packages/` のうち `^packages/(room\|shared-kernel)/` 以外 | docs/architecture の「package と境界」（room の依存してよい先は `shared-kernel`）。npm の依存は制限しない（adapter が 1.5.1 で AWS SDK を使う。domain の純粋さは既存の `domain-is-pure` が守る） |

### 単体テスト（観測点）

すべて `describe` は関数名（図の公開メソッドと一致させる。`check:model-trace` が突き合わせる）。失敗の確認は `isFailure` で絞り込んでから `error.code`（`room.nickname_empty` など）を見る。`code` を見ることで、`RoomError` が packageCode `room` を固定していることも同時に確かめる。**値の比較は `equals` か `value` で行い、`toEqual` で VO 同士を比べない**（ES の private field は `toEqual` の比較対象にならず、違う値でも通ってしまうため）。

`Nickname.test.ts`

- `describe("create")`
  - 前後の空白を除いた値を持つ（`"  たろう  "` → `value` が `"たろう"`）
  - 全角の空白も前後の空白として除く（`"　たろう　"`）
  - 空文字は `room.nickname_empty` で拒否する
  - 空白だけ（半角・全角・タブの混在）は `room.nickname_empty` で拒否する
  - 10 文字ちょうどは受け付ける（`"じゅげむじゅげむごこ"`）
  - 11 文字は `room.nickname_too_long` で拒否する（`"じゅげむじゅげむごこう"`）
  - 前後の空白を除いて 10 文字なら、空白込みで 10 文字を超えていても受け付ける
  - ZWJ で連結した絵文字と国旗を 1 文字として数える（家族の絵文字 10 個は受け付け、11 個は拒否する）
  - 文字の種類を制限しない（漢字・英数字・記号・絵文字の混在を受け付ける）
  - 名前の途中の空白は残す（`"たろう じろう"`）
- `describe("equals")`
  - 同じ値なら等しい
  - 前後の空白だけが違う入力から作ったものは等しい
  - ひらがなとカタカナは別のニックネームとして扱う（`"はなこ"` と `"ハナコ"` は等しくない）
  - 違う値なら等しくない

`RoundCount.test.ts`

- `describe("create")`
  - 下限の 1 と上限の 5 を受け付け、その値を持つ
  - 0 と 6 を `room.round_count_out_of_range` で拒否する
  - 負の数を拒否する
  - 整数でない値（`1.5`）を拒否する
  - `NaN` と `Infinity` を拒否する
- `describe("equals")`
  - 同じ周回数なら等しい／違う周回数なら等しくない

`RoomStatus.test.ts`

- `describe("waiting")`: 待機中の状態はゲームが始まっていない
- `describe("started")`: 始まった状態はゲームが始まっている
- `describe("hasStarted")`: 待機中なら false、始まった状態なら true
- `describe("equals")`: 待機中同士・始まった状態同士は等しい／待機中と始まった状態は等しくない

カバレッジ: `packages/room/src/domain/**` が 4 指標 100%（閾値は 1.1.1 の設定で既に必須）。`errors/RoomError.ts` は値オブジェクトのテストが通る経路で全行を実行する。`RoomErrorCode.ts` は型だけで実行時の文を持たない。`index.ts` は除外済み。

### 境界の手作業確認（コミットしない。1.1.1 からの引き継ぎ）

実装時に一度だけ行い、結果を実装の記録に残す。確かめたら作った違反は消す。

- `npx depcruise packages --config .dependency-cruiser.cjs --output-type json` などで、room の domain から `@eshiritori/shared-kernel` への依存が実パス（`packages/shared-kernel/src/index.ts`）に解決され、依存の種類が npm 系（`npm` `npm-dev` …）でないことを見る。**`domain-is-pure` が workspace の import を誤って止めないこと**（正の確認）
- room の domain から shared kernel の内部 path を相対 path（`../../../../shared-kernel/src/Result`）で import すると `no-cross-package-internals` で失敗する
- `@eshiritori/shared-kernel/src/Result` のような subpath の import は、`exports` が `.` だけなので解決できず `not-to-unresolvable`（と `typecheck`）で失敗する
- room の domain の本番コードから npm パッケージ（例: `vitest`）を import すると `domain-is-pure` と `not-to-dev-dep` で失敗する
- 一時 package（`packages/tmpdep`）を作り、room から import すると `room-depends-only-on-shared-kernel` で失敗する
- `errors/RoomError.ts` から `domain/room/Nickname` を import すると `errors-not-to-layers`（と循環なら `no-circular`）で失敗する

## 5. リスク・注意点

- **dependency-cruiser の workspace の扱い。** symlink 越しの import が実パスに解決されず `node_modules/@eshiritori/shared-kernel/...` のまま残ると、`no-cross-package-internals`（`^packages/` を前提にしている）が効かず、依存の種類が `npm` になって `domain-is-pure` が正しい import を止める。4. の正の確認で見て、ずれていたら `options` の解決設定（symlink の扱い）を直す。ルールの除外で黙らせない
- **knip が値オブジェクトを未使用と報告する場合。** この段の値オブジェクトは公開入口から辿れず、colocate テストからだけ使われる。knip の既定はテストも entry に含むので報告されない見込みだが、報告されたら公開入口に足すのではなく、knip の設定（workspace の entry）が test を entry として拾えているかを直す
- **`toEqual` と private field。** 1-3 で ES の private field にしたため、`toEqual` は値オブジェクトの中身を比べない。後続の段（1.4.1 の `Room`・`Member` のテスト）でも同じ罠があるため、VO の比較は `equals` で書く
- **API 契約の文字数と食い違う。** 1.6.1 で OpenAPI のニックネームに `maxLength: 10` を書くと、JSON Schema はコードポイントで数えるため、ドメインが受け付ける絵文字の名前を入口で拒否する（あるいは空白込みの長さで拒否する）。ニックネームの長さと空の判断はドメインだけが持ち、OpenAPI には長さの制約を書かないよう 1.6.1 に引き継ぐ。周回数の `minimum: 1`・`maximum: 5` も、書くなら同じエラーコードで返るか（入口の検証エラーにならないか）を 1.6.1 で確かめる
- **見た目に空の名前。** ゼロ幅スペース（U+200B）だけの名前は `trim` で除かれず、1 文字として受け付ける。「文字の種類は制限しない」（UC-01 要件 4）に従い、この段では扱わない
- **`Intl.Segmenter` は ICU に依存する。** Node 22 の公式ビルドと Lambda の Node 22 は full ICU を持つので書記素で数えられる。ICU を削ったビルドで動かす場合は数え方が変わる
- **エラーコードを先に定義する。** 1-2 の 9 件は後続の段の設計を先取りしている。後続の段で名前や粒度を変えたくなったら、この段の定義を直してよい（使われるのは後続の段からのため）。その変更は要確認〔予定外〕に載せる
