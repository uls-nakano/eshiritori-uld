# ユースケース定義: 途中で抜ける・戻る

> 置き場: `.designs/REQ-001-eshiritori/UC-05-leave-and-return/usecase.md`
> **観客は業務側です。** 技術仕様（アーキテクチャ・DB 設計・クラス構成）はここに書かず、設計フェーズの成果物に書きます。

## 概要

### 目的

メンバーが待機室やゲームの途中で抜けても、また接続が一時的に切れても、残ったメンバーがゲームを続けられるようにする。一時的に切れた人は、同じプレイヤーとして戻れるようにする。

### スコープ

| 項目 | 内容 |
| --- | --- |
| 対象ユーザー | 部屋のメンバー全員（特にスマートフォンで遊ぶ人） |
| 対象業務 | 待機室・ゲーム中・結果画面で、自分の意思で抜ける場面と、接続が一時的に切れて戻る場面 |
| 対象外 | 開始後の新しいメンバーの途中参加（REQ ヒアリング Q15）、別の端末・別のブラウザからの復帰、メンバーを強制的に退出させる機能 |

### 画面

| 画面名 | モック・参照先 | 補足 |
| --- | --- | --- |
| 待機室・ゲーム画面・結果画面 | `../UC-01-room/mockups/room.html`、`../UC-02-draw-and-guess/mockups/game.html` | 各画面に「抜ける」操作を加える。メンバー一覧・得点表で、接続が切れている人に「切断中」の印を付ける |

## 要件

### 要件 1: 待機室から抜ける

**ユーザーストーリー:** メンバーとして、ゲームが始まる前に部屋から抜けたい。都合が悪くなったときに、残りの人の邪魔をしないためである。

#### 受け入れ基準

1. メンバーが待機室で抜けることを求めたとき(WHEN)、(THEN)システムは、そのメンバーを部屋から外し、残りのメンバー全員のメンバー一覧から消すこと(SHALL)
2. 部屋を作った人が抜けたとき(WHEN)、(THEN)システムは、残りのメンバーのうち最も早く部屋に入った人を新しい部屋を作った人（ホスト）にし、全員に表示すること(SHALL)
3. 部屋の最後のメンバーが抜けたとき(WHEN)、(THEN)システムは、部屋を削除すること(SHALL)

### 要件 2: ゲーム中に抜ける

**ユーザーストーリー:** メンバーとして、ゲームの途中でも抜けたい。残りの人がゲームを続けられるようにするためである。

#### 受け入れ基準

1. 描き手以外のメンバーがゲーム中に抜けたとき(WHEN)、(THEN)システムは、そのメンバーを描く順番と得点表から外し、残りのメンバーで続けること(SHALL)
2. 描き手がターンの途中で抜けたとき(WHEN)、(THEN)システムは、そのターンをパスと同じ扱いで終え、次の描き手に交代すること(SHALL)
3. 抜けた結果、残りのメンバーが 1 人になった場合(IF)、(THEN)システムは、ゲームを終え、残ったメンバーに結果を表示すること(SHALL)
4. ゲームが終わったとき(WHEN)、(THEN)システムは、途中で抜けたメンバーを結果の順位に含めないこと(SHALL)

部屋を作った人がゲーム中・結果画面で抜けた場合のホストの引き継ぎは、要件 1-2 と同じです。

### 要件 3: 接続が切れて戻る

**ユーザーストーリー:** スマートフォンで遊ぶメンバーとして、画面がスリープしても同じプレイヤーとして戻りたい。それまでの順番と得点を失わないためである。

#### 受け入れ基準

1. メンバーの接続が切れたとき(WHEN)、(THEN)システムは、そのメンバーをメンバー一覧・得点表に残したまま「切断中」の印を全員に表示すること(SHALL)
2. 接続が切れたメンバーが同じブラウザで部屋のページを開き直したとき(WHEN)、(THEN)システムは、そのメンバーを同じプレイヤーとして、描く順番と正解数を保ったまま、現在の画面（待機室・ゲーム中のターン・結果）に戻すこと(SHALL)
3. 接続が切れているメンバーに描き手の番が来た場合(IF)、(THEN)システムは、その番をお題を決める前のパスと同じ扱いで終えること(SHALL)
4. 描き手の接続がターンの途中で切れ、30 秒以内に戻らなかった場合(IF)、(THEN)システムは、そのターンをパスと同じ扱いで終えること(SHALL)
5. 部屋を作った人（ホスト）の接続が切れ、30 秒以内に戻らなかった場合(IF)、(THEN)システムは、要件 1-2 と同じ順で接続中のメンバーにホストを引き継ぐこと(SHALL)

### 要件 4: エラー・境界条件

**ユーザーストーリー:** メンバーとして、戻れない場合はその理由を知りたい。

#### 受け入れ基準

1. 別の端末・別のブラウザから、ゲーム中の部屋に同じニックネームで入ろうとした場合(IF)、(THEN)システムは、UC-01 と同じくゲーム中のため入れない旨を表示すること(SHALL)
2. 削除された部屋のページを開き直した場合(IF)、(THEN)システムは、部屋が見つからない旨を表示すること(SHALL)

## 非機能要件

| 観点 | 要件 |
| --- | --- |
| 性能 | 退出・切断・復帰が、ほかのメンバーの画面に 1 秒以内に反映される（ローカル環境）。接続の切断は 10 秒以内に検知する |
| 認可・セキュリティ | 同じプレイヤーとして戻れるのは、そのプレイヤーとして部屋に入ったブラウザだけ。ニックネームを知っているだけでは、ほかの人になりすませない |
| データ量 | UC-01 と同じ（記録は最後の更新から 24 時間で削除） |
| 可用性 | 接続が切れている間もゲームの状態は失われない |
| 監査 | 記録しない |
