# ドメインモデル

ドメインモデルをパッケージごとのフォルダに記述します。パッケージ内の集約俯瞰図は各パッケージの README に、パッケージをまたぐ関係はこのドキュメントにあります。図の記法は [rules/model-design](../../rules/model-design/standard.md)、図と実装の対応は `npm run check:model-trace` が機械で突き合わせます（フォルダ名が `uld.config.json` の `domainSources` に対応します）。

- [ユビキタス言語](ubiquitous-language.md) — ドメイン用語の定義（パッケージ横断）

## パッケージ一覧

| パッケージ | 扱う業務 | ドキュメント |
| --- | --- | --- |
| `room` | 部屋を作る・部屋に入る・ゲームを始める | [room/](room/README.md) |

パッケージをまたぐ関係はまだありません。後続のゲームの進行（ターン・お題・描画・回答）は別のパッケージに置く想定で、部屋からは描く順番とメンバーを受け取ります（[docs/architecture](../architecture/README.md) の「package と境界」）。

## 保存の大原則

- **1 集約 = 1 項目。** 部屋は、メンバーの一覧（開始後はその並びが描く順番）まで含めて 1 件で保存・復元します。満員・ニックネームの重複・開始できるかの判断は、部屋の集約 1 つを読めば完結します
- **同時の更新は改訂番号で先着順にする。** 部屋は保存のたびに改訂番号が 1 つ進み、読んだときの改訂番号と一致するときだけ書き込めます。一致しなければ読み直して判断をやり直します
- **期限切れはドメインが判断する。** 最後の更新から一定時間たった部屋は、物理的に削除されたかどうかに関わらず「存在しない」として扱います（[docs/architecture](../architecture/README.md) の「データの保存と期限」）
