# ユースケース記述

システムの現在の振る舞いを、利用者目線のフロー（正常系・異常系）で表す生き資料です。フローの各所に埋め込んだ受け入れ基準の ID がテストコードとのトレースの結合キーになります。ID の形式・運用とテスト名への埋め込み方は [rules/acceptance-testing](../../rules/acceptance-testing/standard.md) の「仕様トレーサビリティ」を参照してください。

- 要求の経緯（ヒアリング・シナリオ・当時の合意）は [.designs/](../../.designs/) にログ資料として残っています。ログは書き換えないため、テストからのリンク対象にしません
- ID の直後の状態マークは、「（未実装）」が設計フェーズで合意済みで実装がまだの基準、「（廃止予定）」が置き換え先の実装を待っている基準、「（廃止）」が退役して欠番として残した基準です。マーク無しが効いている基準で、テストの有無と機械で突き合わせています（`npm run check:trace`）
- 複数のユースケースを貫くジャーニーは [docs/journeys/](../journeys/README.md) にあります。E2E テストの対象で、受け入れ基準は定義しません
